Sales Playbook

How to run every conversation — from first hello to signed deal.

Discovery questions

What does your business do and how do you currently handle [orders / jobs / tickets]?Understand what's broken — they'll tell you exactly why they need you.
What's your biggest frustration with how you handle it today?Pain = motivation. If there's no pain, there's no urgency. Dig here.
Do your customers ever ask if you have an app or online ordering?Almost always yes — lets them feel the demand they're missing out on.
Have you looked at other options before? What put you off?Price shock from agencies, complexity of Shopify, failed DIY attempts. Position against their bad experience.
What would a successful solution look like for you in 3 months?Anchor them to an outcome. Makes the close easier — just confirm you can deliver that outcome.

Closing the deal

The assumptive close"Great — I'll get this across to the team today. Did you want to kick things off with Stripe for payments, or do you use PayPal?"
The summary close"So we're looking at a [App Type] for [Business Name] — $[setup] setup, $[monthly]/month, live within a week. Does that work?"
The urgency close"We can have it live before [upcoming event/busy season]. If we start this week, you'll be taking orders online by [date]."
After they say yesMark the lead as Won in My Leads, note the agreed price, and message the boss. That's it — you're done.

Objection Handling

Every objection you'll hear and exactly what to say.

"It's too expensive."
Ask them what they're comparing it to. If it's DIY: "Wix and Shopify charge $50–$100/month and you still have to build it yourself — this includes everything, fully built, plus ongoing support." If it's an agency: "You're looking at $5,000–$15,000 with an agency for a fraction of the features. We're a fraction of that."
"I need to think about it."
"Of course — what's the main thing you need to think through? Is it the price, or how the app would actually work for your business?" Then address that specific thing. If they're genuinely not ready, book a follow-up call in the diary before you hang up.
"We already have a website."
"That's fine — this works alongside it. Your website tells people about you, this lets them actually do something: order, buy a ticket, book a job. They're different tools."
"Can't I just use Shopify / Wix / Square?"
"You can — but Shopify is $79+/month before any apps, takes weeks to set up, and isn't built for Australian businesses. We're live in under a week, cheaper, and it's fully branded to them with no PennyWiseIT branding anywhere."
"What happens if you go out of business?"
"The app runs on Cloudflare — one of the largest infrastructure companies in the world. Even if we disappeared tomorrow, the app stays live as-is. We can also give you the code if that's a genuine concern."
"I need to talk to my partner / accountant."
"No worries — can I send you a one-page summary you can forward to them? And should I follow up with you on [specific day]?" Get the follow-up booked before the call ends.

My Tools

Your tools — what they actually do

Plain English. You run these commands in your terminal.

🔨
The App Builder
npm run compose -- --config examples/client.json
Takes a client config file (their name, template, features) and generates their entire app — all the code, database setup script, and deployment config. Nothing is deployed yet, it just creates the files.
Use when: starting work on a new client app, or rebuilding an existing one.
🚀
The One-Click Deployer
npm run deploy -- --config examples/client.json
Does everything in sequence: builds the app, creates the database on Cloudflare, runs the database setup, deploys the app live to the internet, and registers it with your monitoring dashboard.
Use when: deploying a finished app for the first time, or redeploying after major changes.
🕵️
The Drift Checker
npm run drift -- --config examples/client.json --fix
Checks if a client's live database matches what it's supposed to look like. If something's missing or changed, it tells you exactly what's wrong and gives you the commands to fix it.
Use when: a client reports something broken, after adding new features, or for a routine health check.

The Monitoring Dashboard

A live web dashboard showing the health of all your deployed apps. Green means everything's working, yellow means needs attention, red means something's down. Run a validation check on any app from here.

The Feature Registry
pennywiseit-registry.workers.dev
A searchable catalogue of all your app types and plug-in modules. Use it when quoting a new client to quickly see what's available, what each module costs, and what API keys you'll need from the client.
Use when: scoping a new client, or showing a prospect what you can build for them.

The Manifest Linter
npm run validate-manifest
Checks that your feature module definitions are correct and complete. Stops bad config from making it into a client's app. You don't need this often — mostly useful when you're adding a brand new feature module.
Use when: you've created a new feature module and want to make sure it's configured correctly.
